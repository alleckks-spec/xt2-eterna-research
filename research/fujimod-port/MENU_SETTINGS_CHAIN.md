## New combined chain

hook once (four init/two late functions). The catalog starts before settings
from the real timer-slot order; both native worker frames remain live across
catalog and SETTINGS.JSN open/read/close. The supplied settings document has

restored ETERNA choice without an additional selection setter.

On that same loaded-owner machine, `--menu-flow` in
`verify_full_storage_guard.py` executes the original firmware menu event

actual parent has nine rows (eight stock plus the added row); its option has
two choices. The firmware itself sets menu_open=1. The host never writes that
flag in this check.

The supplied environment stays REC3 throughout. Testing only in SETUP_REC5
would be insufficient: settings already declines work outside REC3, which
would obscure whether menu_open matters.

## Reproduce the combined case

From the prepared workspace with authorized local firmware/upstream inputs:

```sh
PYTHONPATH="$PWD/scripts:$PWD/ports/fujimod-xt2" \
LIBUNICORN_PATH="$PWD/.toolchains/unicorn-tci" UC_IGNORE_REG_BREAK=1 \
.venv/bin/python ports/fujimod-xt2/verify_full_storage_guard.py \
  --case restore --saved-choice eterna \
  --date-card-name 1 --date-folders 0 --menu-flow \
  --build ports/fujimod-xt2/save-data-menu-native-build-unverified \
  --output ports/fujimod-xt2/NEW_MENU_CHAIN_REPORTS
```

The existing approved local unsandboxed TCI execution is required on this
machine. This reuses the prepared native helpers rather than constructing a
new runtime, service, menu architecture or SD model.

## Not proved and next dependency

Native constructors, borrowed UI1, REC/calibration/settings inputs, explicit
timer ticks and the existing downstream initializedFS/post-FAT frame remain
declared fixtures. This does not execute a full reset boot or physical MENU,
OK/BACK input routing. A stock bank operation is exercised at its real entry;
the native-menu worker's packet-level checks remain separate evidence.

The new result proves menu value changes reach the loaded shared owner,
preserves the unrelated film selection and demonstrates the real native
menu-open gate postpones file issue until native close. It does not prove
successful settings persistence. Next dependent step remains genuine native
write-driver bootstrap/registration, then write/count/close/readback/restore.
Capture admission, task-context issue, lost requests, DMA/cache, C1-C7,
physical SD/power-off and camera image/encoder behavior remain open.
