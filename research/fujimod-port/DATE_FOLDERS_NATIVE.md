# Native A/B date folders: software function stage

The normal auto(-1) path now reaches date-folder logic through the existing native A and B name producers. This supersedes the explicit-A-only diagnostic. It is a native function and native menu result, not a camera acceptance, full boot, completed mount, physical capture or successful file-write result.

Primary: `date-folders-dual-stable-build-unverified`; fresh reproduction: `date-folders-dual-stable-rebuild-unverified`. Both use ELF SHA-256 `0cbd4cb60b86c984a09c2809ef7faf265fe4a29eebd97bc36ac3ba6db79f0d87`, region SHA-256 `dc24f9fd64ecdf5f1d26908fb80e4d9280bcb1faccd03a45ec8f173f6b1f77a1`, 247600 bytes, 76 words, 39 C sources and 14 libraries. The existing 0x1380000..0x13c0000 reservation has 14544 bytes remaining; real workload heap/stack headroom remains unproved. The preparation receipt retains the complete selected source and metadata closure from the frozen native SAVE DATA base.

The selected existing prototype is adapted as two instances with separate per-owner state and the real native-owned catalog context. Each native module constructor declares 0x1878c bytes. Its own scan writers publish directory ownership, clusters, suffix entries and numeric filename reservation. The suffix table's maximum end 0x17f88 is inside that allocation. The host supplies explicit mount-command parameters and post-enumeration FAT entries, not a ready flag or registered object pointer. Both module registrations execute natively. The partial scan fixture has no recognized-extension registration, so the file entry proves numeric filename reservation, not a recognized JPEG count or completed mount.

Bindings are to the actual native A/B producer entries and their suffix-read BL callsites. Each suffix adapter reads that module's owned per-drive suffix. There is no production frame walk, mutable A scope latch, global configured-suffix change or observed heap-name pointer. The shared settings owner and existing menu engine remain responsible for configuration.

The native baseline proves that name generation, explicit A/B callers and CEC148 auto arbitration do not commit the shared FRAME NO pair. Each adapter therefore wraps its original producer using existing XPP_STOCK, applies the prototype's candidate decision, runs the real native producer, then restores the pair before returning every native status. The real candidate buffer and status remain available to ordinary native arbitration. Native counter consumers after the storage-operation boundary retain ownership of committed values.

A name request alone is not folder creation. New-day decisions are re-derived until the catalog contains the dated folder. OFF uses the current native catalog suffix to decide whether a fresh stock-suffixed folder is still needed, so repeated OFF requests remain stable. This corrected an observed first/repeated-OFF discrepancy in the earlier 1f0a6b artifact, which is not the final candidate.

The exact native checks cover 48 successful date/edge calls, six exhausted-range errors, twelve explicit native refusal calls and 24 OFF baseline-equivalence calls. A, B and auto are each repeated without capture. Cases include a new day, both owners continuing, mixed continuation/new owner, B's newer folder, B's larger file number, empty catalogs, invalid month/day and exhausted DCF numbering. Shared counter bytes are unchanged on every return, including errors; error outputs remain untouched. Each measured call preserves r4-r11, d8-d15 and SP. The refusal fixture supplies an explicit lower-boundary device-status snapshot to the actual native status publisher; no callback or successful API return is replaced.

Stock arbitration is independently measured with equal and divergent catalogs. It executes both native candidate producers and parses their actual buffers, merges the selected numbers into the A candidate, and leaves the shared counter pair unchanged. For example, A 100/1 plus B 101/1001 produces auto `A:\DCIM\101_FUJI\DSCF1002`. With date folders, the real auto path produces the corresponding dated name. These are function results with supplied catalog inputs, not physical dual-card captures.

Same-machine transition checks cover OFF with and without an already published dated catalog, repeated requests and the next calendar day. An actual returned `A:\DCIM\102_1112\DSCF2001` is also accepted by the native counter-consumer lower boundary: previous/current folder 102/102, file 2001 and prior suffix `_1112`. That consumer executes separately after the storage-operation boundary; the preceding native device call is stopped before execution. No successful open, completed capture or filesystem result is supplied or claimed.

Both linked SAVE DATA items pass actual native list/cursor/resource, internal option packet, preview, cancel, commit, save-generation, codec and caption/font checks.
